位置情報ゲームのサーバーは、クライアントから送られてくる座標を信じるしかない。しかし端末側で座標を偽装するのは難しくなく、開発者オプションの「疑似ロケーション」を使えば誰でもできてしまう。ここでは実際に効いた判定と、効かなかった判定を書いておく。

## 速度による判定

最初に入れたのは移動速度のチェックだった。連続する二点の距離を経過時間で割るだけの単純なものだ。

```python
def speed_kmh(p1, t1, p2, t2):
    meters = haversine(p1, p2)
    seconds = (t2 - t1).total_seconds()
    if seconds <= 0:
        return float("inf")
    return meters / seconds * 3.6
```

閾値を超えたら警告を積む。ここで問題になるのが閾値の決め方で、以下のような分布を想定する必要がある。

| 移動手段 | 想定速度 | 判定 |
| --- | --- | --- |
| 徒歩 | 4 km/h | 正常 |
| 自転車 | 20 km/h | 正常 |
| 自動車 | 60 km/h | 正常 |
| 新幹線 | 300 km/h | 要注意 |
| それ以上 | — | 偽装の疑い |

> 新幹線を切り捨てると、東京から大阪へ移動する正規のプレイヤーが全員 BAN される。日本でサービスを出す以上ここは外せない。

### GPS の誤差という落とし穴

さらに厄介なのは、静止していても座標が揺れることだ。ビルの谷間では誤差が 50 メートル以上出る。1 秒間隔で送信していれば、動いていないのに 180 km/h と計算されてしまう。

対策として次の三つを入れた。

1. 端末が報告する精度 (`horizontalAccuracy`) が悪い点は破棄する
2. 誤差半径の合計より短い移動距離は 0 として扱う
3. 単発では判定せず、直近 10 点の中央値を見る

## 効かなかったもの

- **加速度センサーとの突き合わせ** — 偽装アプリはセンサー値も一緒に偽装してくる
- **IP アドレスの地域** — モバイル回線では基地局の位置が実際とかけ離れることが多く、誤検出が多すぎた
- **端末のルート化検出** — いたちごっこになり、しかも正規ユーザーを巻き込む

## 今の方針

即座に BAN はしない。スコアを積んでいき、閾値を超えたアカウントは**そのプレイヤーの行動だけ他プレイヤーから見えなくする**。誤検出のコストが非対称だからだ。偽装者を一人見逃す損失より、正規のプレイヤーを一人 BAN する損失のほうがはるかに大きい。
